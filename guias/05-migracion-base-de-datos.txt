================================================================================
  GUÍA: MIGRACIÓN E INICIALIZACIÓN DE BASE DE DATOS
================================================================================

1. INICIALIZACIÓN AUTOMÁTICA (DOCKER)
--------------------------------------
  Al crear el contenedor postgres por primera vez, Docker ejecuta:
    database/init.sql

  Contenido principal:
    - Tablas fondo y sub_fondo (catálogo archivístico)
    - Tablas documentales (actas_sesiones, proyectos_ley, etc.)
    - registro_operaciones + función fn_auditoria + triggers
    - Datos semilla de fondos y subfondos
    - Tablas de soporte para cargas y duplicados (según versión del script)

  El volumen pgdata persiste los datos entre reinicios.


2. PERSISTENCIA AL REINICIAR SERVICIOS
------------------------------------
  Los datos de PostgreSQL se guardan en el volumen Docker:
    archivo_congreso_pgdata

  Comandos que CONSERVAN los datos:
    docker-compose stop
    docker-compose start
    docker-compose restart
    docker-compose up
    docker-compose up --build

  Comando que BORRA los datos (evitar en producción):
    docker-compose down -v
    El flag -v elimina los volúmenes nombrados.

  El proyecto usa nombre fijo "archivo-congreso" en docker-compose.yml para
  que el volumen no cambie si renombras la carpeta del proyecto.

3. RESETEAR BASE DE DATOS (DESARROLLO / TESTING)
------------------------------------------------
  ADVERTENCIA: Borra todos los datos.

    docker-compose down -v
    docker-compose up --build

  init.sql solo se ejecuta la primera vez que el volumen pgdata está vacío.


4. MIGRACIÓN SIN DOCKER
-----------------------
  1. Instalar PostgreSQL 15+.
  2. Crear base archivo_congreso y usuario con permisos.
  3. Ejecutar:
       psql -U congreso -d archivo_congreso -f database/init.sql
  4. Ajustar DATABASE_URL en .env del backend.
  5. Iniciar backend; ensure_users_table() crea tabla usuarios y admin.


5. AÑADIR TABLAS NUEVAS A UNA BD EXISTENTE
------------------------------------------
  Opción A — Editar init.sql y recrear volumen (solo si puede perder datos).
  Opción B — Ejecutar SQL manualmente en producción:

    CREATE TABLE nueva_tabla (...);
    INSERT INTO sub_fondo (...) VALUES (...);
    Añadir entrada en backend/tables_config.yaml;
    docker-compose restart backend.


6. TABLAS DE SOPORTE DE CARGA (CREADAS EN RUNTIME)
--------------------------------------------------
  El backend puede crear si no existen:
    - carga_archivos
    - carga_registros_hash
    - usuarios (security.ensure_users_table)
    - archivo_cargado, carga_duplicados_bd, carga_duplicados_archivo
      (según implementación en documentos.py e init.sql)


7. SEMILLA DE HASHES PARA TABLAS CON DATOS PREVIOS
--------------------------------------------------
  En la primera carga a una tabla que ya tiene filas, _seed_existing_hashes()
  rellena carga_registros_hash desde los datos existentes para detectar
  duplicados correctamente.


8. BACKUP RECOMENDADO (PRODUCCIÓN)
----------------------------------
  Antes de migraciones:

    docker exec <contenedor_postgres> pg_dump -U congreso archivo_congreso \
      > backup_YYYYMMDD.sql

  Restaurar:

    psql -U congreso -d archivo_congreso < backup_YYYYMMDD.sql


9. AUDITORÍA Y TRIGGERS
-----------------------
  Cada tabla documental puede tener trigger que llama fn_auditoria.
  El usuario registrado es el de la aplicación (JWT), vía variable de
  sesión app.audit_user, no el rol PostgreSQL.

  Durante carga masiva los triggers permanecen activos: cada INSERT
  queda en registro_operaciones con el username del operador.

  Migración en BD existente:
    psql -U congreso -d archivo_congreso -f database/migrations/001_auditoria_archivos_fondo.sql


10. ARCHIVOS CARGADOS Y REVERSIÓN
---------------------------------
  archivo_cargado guarda nombre, ruta, hash, usuario y fecha.
  carga_archivo_registro vincula cada fila insertada (id_registro + hash).
  El módulo Registro → «Archivos cargados» permite revertir una carga
  (conteo previo + confirmación escribiendo el nombre del archivo).
