================================================================================
  GUÍA: INSTALACIÓN Y EJECUCIÓN DEL PROYECTO
  Archivo Congreso — Gestión documental
================================================================================

1. REQUISITOS PREVIOS
---------------------

  Obligatorio:
    - Docker Desktop instalado y en ejecución (Windows, macOS o Linux).

  Opcional:
    - Git para clonar el repositorio.
    - PowerShell, CMD o terminal equivalente.

  Verificar Docker:
    docker --version
    docker run hello-world


2. OBTENER EL PROYECTO
----------------------

  Con Git:
    git clone <URL_DEL_REPOSITORIO>
    cd Desarrollo_informacion_descripcion

  Sin Git:
    Descargar ZIP, extraer y abrir terminal en la carpeta raíz (donde está
    docker-compose.yml).


3. ESTRUCTURA MÍNIMA ESPERADA
-----------------------------

  backend/          API FastAPI
  frontend/         Interfaz React + Vite
  database/init.sql Esquema e datos iniciales PostgreSQL
  docker-compose.yml
  .env              Variables de entorno
  guias/            Esta documentación


4. CONFIGURACIÓN (.env)
-----------------------

  El archivo .env define credenciales de PostgreSQL y la URL de conexión.
  Valores por defecto (solo desarrollo):

    POSTGRES_USER=congreso
    POSTGRES_PASSWORD=congreso123
    POSTGRES_DB=archivo_congreso
    DATABASE_URL=postgresql://congreso:congreso123@postgres:5432/archivo_congreso

  En producción cambie contraseñas y TOKEN_SECRET antes de desplegar.


5. EJECUCIÓN CON DOCKER (RECOMENDADO)
-------------------------------------

  Primera vez (descarga imágenes y compila):
    docker-compose up --build

  Siguientes veces:
    docker-compose up

  En segundo plano:
    docker-compose up -d

  Esperar mensajes de:
    - postgres: database system is ready
    - backend: Uvicorn running on http://0.0.0.0:8000
    - frontend: VITE ready

  Servicios:
    Frontend:  http://localhost:3000
    API docs:  http://localhost:8000/docs
    PostgreSQL: localhost:5432


6. EJECUCIÓN MANUAL (SIN DOCKER)
--------------------------------

  A) Base de datos — PostgreSQL en localhost:5432 con datos del .env, o solo BD:
     docker run -d -e POSTGRES_USER=congreso -e POSTGRES_PASSWORD=congreso123
       -e POSTGRES_DB=archivo_congreso -p 5432:5432 postgres:15-alpine

  B) Backend:
     cd backend
     python -m venv venv
     venv\Scripts\activate          (Windows)
     source venv/bin/activate       (Linux/macOS)
     pip install -r requirements.txt
     uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

  C) Frontend (otra terminal):
     cd frontend
     npm install
     npm run dev


7. VERIFICACIÓN
---------------

  docker ps                    → 3 contenedores: postgres, backend, frontend
  http://localhost:8000/docs   → Swagger UI
  http://localhost:3000        → Pantalla de login

  Usuario inicial: admin / admin123 (creado automáticamente si no hay usuarios).


8. SOLUCIÓN DE PROBLEMAS FRECUENTES
-----------------------------------

  Docker no reconocido:
    Instalar Docker Desktop y reiniciar la terminal.

  PostgreSQL no inicia:
    docker-compose down -v
    docker-compose up --build

  Puerto en uso (3000 u 8000):
    netstat -ano | findstr :3000
    taskkill /PID <PID> /F
    O cambiar puertos en docker-compose.yml.

  Frontend sin conexión al API:
    Comprobar backend: curl http://localhost:8000/docs
    docker-compose restart backend

  Despliegue externo (dominio público):
    Definir en .env:
      VITE_API_URL=https://api.tu-dominio.com/api
    Luego reconstruir frontend:
      docker-compose up --build -d frontend

  npm install falla:
    npm cache clean --force
    npm install


9. COMANDOS ÚTILES
------------------

  docker-compose stop
  docker-compose down
  docker-compose down -v          (BORRA TODOS LOS DATOS — no usar para reiniciar)
  docker-compose restart          (reinicia sin perder datos)
  docker-compose logs -f backend
  docker-compose restart backend

  Ver también: 05-migracion-base-de-datos.txt
